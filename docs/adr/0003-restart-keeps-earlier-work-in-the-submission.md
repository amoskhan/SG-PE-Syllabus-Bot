# A restart keeps the earlier work inside the same submission

When the teacher clears a pair's check-in, the pair restarts: they check in again (on any device) and start the lesson's work from Step 1. Everything they had sent stays in the same submission as earlier work, with its locks and grades, until the teacher removes it, and the restart's new work starts open. We keep it in the same submission, not a second submission for the pair number, because a restart is the same two pupils (a pair is fixed for a lesson): the teacher should see all their work in one place, and their PE AI Buddy limits, counted by pair number, carry over. Unlike a redo request, which replaces the old attempt, a restart never replaces anything: teachers clear a check-in when pupils want to start over or have lost their work, and must never lose what was already sent.

## Considered Options

- **A new submission per restart** ("Pair 5" and "Pair 5 · Restart 1"): rejected, it splits one pair's work across Review Tray entries and breaks "one submission per pair per lesson".
- **Overwrite, as before**: rejected, it is how work was being lost (#173).

## Consequences

- The earlier work is set aside the moment the teacher clears the check-in, so a slow save from the pupils can't mix old and new work.
- Clearing a check-in also frees the pair number from the device that held it, so a pair who lost their work can carry on from another device.
- Only the teacher removes earlier work, one go at a time or the whole submission.
